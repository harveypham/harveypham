# Conceptual Work Directory Structure
<p align="right">Refined with assistance of AI tools</p

The `concepts` folder structure demonstrates the principle at multiple levels simultaneously.

## Structure

```
concepts/
  PRINCIPLES/
    put-related-things-together-unrelated-things-apart/
      README.md
      practice-notes.md
```

## Boundary Mapping

**Directory depth** maps to conceptual scope:
- First level (`PRINCIPLES/`, `MODELS/`) — categories of conceptual work
- Second level (`put-related-things-together.../`) — individual conceptual works

Directory depth carries the boundary signal, but the signal is weak — it requires the reader to mentally track depth to infer meaning.

**Capitalization** amplifies the signal, making the boundary immediately visible at a glance:
- Capitalized directories — categories
- Lowercase directories — individual works

**`README.md`** is a physical boundary — the platform (GitHub, etc.) promotes it to directory-level representation, making it the face of the directory rather than a file within it. Capitalization here is convention; the structural promotion is what matters.

Lowercase files (`practice-notes.md`) — supporting content within the work
